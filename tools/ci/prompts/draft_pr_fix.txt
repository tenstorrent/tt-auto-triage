   - **C++/gtest:** `GTEST_SKIP() << "Root cause unclear, disabled by auto-triage. See __ISSUE_URL__";`
   - **Other:** Use the framework's standard skip/disable mechanism on the narrowest possible scope

## CRITICAL Rules

- Keep changes minimal and focused.
- TARGET THE NARROWEST SCOPE POSSIBLE for any disable/skip. If one test out of 50 fails, skip only that one. If one parametrized variant out of 10 fails, skip only that variant.
- NEVER disable an entire CI job in a YAML pipeline config (e.g. commenting out a job entry in tests/pipeline_reorg/*.yaml). Those jobs run many tests — disabling the whole job kills all of them.
- NEVER comment out workflow steps, job definitions, or entire test files when only specific test cases fail.
- Do NOT refactor or clean up unrelated code.
- Do NOT modify tests that are not related to this failure.
- Prefer a targeted fix over a broad refactor.
- If unsure, fall back to disabling ONLY the specific failing test rather than making a potentially incorrect fix.
